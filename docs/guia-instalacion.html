Guía de instalación, de cero a funcionando

Esta guía te lleva de una máquina vacía al sistema abierto en tu navegador. El montaje en sí es un solo comando; después hay una sección que explica, sin apuro, qué hizo ese comando por dentro. Si es tu primera vez con Docker, leé las dos partes.

El objetivoQué vas a instalar

Un sistema web de inventario de productos con login: podés crear, listar, editar y eliminar productos, con usuarios y recuperación de contraseña. Está hecho en PHP + MySQL, y cada pieza corre en su propio contenedor de Docker.

¿Qué es un contenedor?

Una caja aislada y liviana que trae adentro un programa ya instalado y listo para correr. La ventaja es que no tenés que instalar MySQL ni PHP en tu computadora: los bajás ya armados y los prendés. Y cuando no los querés más, los apagás y no queda nada dando vueltas.

Vamos a levantar tres cajas, y Docker las va a conectar entre sí:

tarea_crud_mysqlLa base de datos: acá se guardan los productos y los usuarios.
tarea_crud_phpLa aplicación: el servidor web que ejecuta las páginas que vas a usar.
tarea_crud_phpmyadminUn panel para mirar la base desde el navegador. Es opcional, pero cómodo.

Los nombres empiezan todos con tarea_crud_ a propósito: así este proyecto no se mezcla con ningún otro que ya tengas en Docker.

Antes de empezarRequisitos

Solo necesitás tres cosas. En el Paso 1 te muestro cómo instalar las dos primeras según tu sistema operativo.

  • Docker Desktop — el motor que corre los contenedores.
  • Git — para descargar el proyecto desde GitHub.
  • Un navegador (Chrome, Edge, Firefox…) — ya lo tenés.

Recomendado: VSCode para ver y editar el código con comodidad.

Paso 1Instalá los requisitos según tu sistema

Elegí tu sistema operativo. Solo tenés que hacer la pestaña que te corresponde.

1

Activar WSL 2

Docker en Windows necesita WSL 2 (un Linux liviano por debajo). Abrí PowerShell como administrador y corré:

wsl --install

Reiniciá la computadora si te lo pide.

2

Instalar Docker Desktop

Descargá Docker Desktop for Windows desde docker.com, instalalo y abrilo. Esperá a que el ícono diga "Engine running".

3

Instalar Git

Descargá Git for Windows desde git-scm.com e instalalo con las opciones por defecto. Vas a usar la terminal Git Bash que trae.

Verificá

Abrí Git Bash y corré docker --version y git --version. Si ambos muestran un número de versión, estás listo.

1

Instalar Docker Desktop

Descargá Docker Desktop for Mac desde docker.com. Elegí la versión correcta: Apple Silicon (M1/M2/M3) o Intel. Arrastralo a Aplicaciones, abrilo y esperá a que diga "Engine running".

2

Instalar Git

Abrí la Terminal y corré git --version. Si no lo tenés, macOS te ofrece instalar las herramientas de desarrollo; aceptá. (O con Homebrew: brew install git.)

Verificá

En la Terminal corré docker --version y git --version. Si ambos muestran versión, estás listo.

1

Instalar Docker

En Ubuntu/Debian (para otras distros, mirá la guía oficial):

sudo apt update
sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER

Cerrá sesión y volvé a entrar para usar Docker sin sudo.

2

Instalar Git

sudo apt install -y git
Verificá

Corré docker --version y git --version. Si ambos muestran versión, estás listo.

Paso 2Levantar el proyecto

Son cuatro pasos, todos escritos en una terminal (Git Bash en Windows; Terminal en macOS o Linux): te parás dentro de la carpeta del proyecto, escribís o pegás cada línea y presionás Enter. Este es el recorrido completo de un vistazo:

Dos cosas que conviene entender antes de empezar

1) La contraseña de la base la inventás vos. No hay que buscarla en ningún lado ni sacarla de ningún sitio. Elegís una, la escribís en un archivo, y listo. Se usa en un solo lugar, así que no hay nada que "hacer coincidir".

2) Primero se baja el proyecto, después se levantan los contenedores. Nunca al revés. La aplicación PHP se arma con los archivos del repositorio, así que sin tenerlos no habría con qué armarla.

1

Bajar el proyecto

Ubicate donde quieras guardarlo (por ejemplo el Escritorio, con cd Desktop). El comando git clone crea una carpeta nueva con todo adentro, y cd entra en ella:

git clone https://github.com/ra3gar/tarea_crud_php.git
cd tarea_crud_php

A partir de acá la terminal queda "parada" dentro de la carpeta del proyecto. No la cierres: los comandos que siguen se corren desde ahí.

2

Elegir tu contraseña

El proyecto trae una plantilla llamada .env.example. Copiala con el nombre .env:

cp .env.example .env

Ahora abrí ese .env con un editor de texto. Lo más cómodo es VSCode: Archivo → Abrir carpeta… y elegís la carpeta del proyecto. Dentro vas a encontrar una línea así, y le cambiás el valor por una clave inventada por vos:

DB_PASS=mi_clave_local
¿Por qué en un archivo y no en el comando?

Porque las contraseñas no se suben a GitHub. El .env figura en el .gitignore, así que tu clave se queda en tu computadora y nunca viaja al repositorio. La base de datos y la aplicación van a usar las dos esa misma clave, pero vos la escribís una sola vez y en un solo lugar.

¿En qué momento se hace esto?

Justo acá: después de clonar el proyecto (Paso 1) y antes de levantar los contenedores (Paso 3). El orden importa porque Docker lee el .env al arrancar: si todavía no existe, el comando del Paso 3 falla con un aviso de que falta DB_PASS. Se hace una sola vez; en los arranques siguientes el .env ya está y no hay que tocarlo.

3

El comando

Antes de correrlo, asegurate de dos cosas: que el archivo .env ya exista (Paso 2) y que Docker Desktop esté abierto — el ícono de la ballena, que diga "Engine running". Después:

docker compose up -d --build

La primera vez tarda unos minutos: tiene que descargar MySQL y phpMyAdmin, y armar la imagen de la aplicación. Vas a ver mucho texto pasando por la pantalla; es normal y no hay que leerlo. Las veces siguientes arranca en segundos.

¿Qué significan esas letras?

up quiere decir "levantá todo". -d es "dejalo corriendo en el fondo y devolveme la terminal". --build es "armá primero la imagen de la aplicación". La primera vez hacen falta las tres; después basta con docker compose up -d.

4

Abrir la aplicación

Andá a http://localhost:8001. Te va a recibir la pantalla de login.

La base arranca con un usuario administrador ya cargado: usuario admin, contraseña Inicio01a. Podés entrar con ese para gestionar todo, o hacer clic en "Crear cuenta" y registrarte con tu nombre y apellido (campos separados), un usuario y una contraseña (esa cuenta será un usuario normal, porque ya existe un administrador). Adentro vas a ver la lista con 5 productos de prueba que el proyecto trae cargados.

Cuenta de administrador por defecto

Usuario admin / contraseña Inicio01a. Es una credencial educativa; en un sistema real, lo primero sería cambiarla.

Si ves los 5 productos, terminaste

Esa lista es la mejor señal de que todo funcionó: significa que la aplicación corre, que se conectó a la base, y que la base se creó con sus tablas y sus datos.

Para entenderQué pasa por dentro

Ese comando no es magia, y vale la pena saber qué hizo — sobre todo el día que algo falle. Levantó los tres contenedores, les armó una red privada para que se hablen entre ellos, y le dio a la base un lugar aparte donde guardar lo que escribe.

El rol de Docker: qué problema resuelve

Antes de Docker, para correr este proyecto había que instalar a mano PHP, MySQL y Apache en cada computadora, con la versión correcta de cada uno, y cruzar los dedos para que no chocaran con algo ya instalado. Es el clásico "en mi máquina funciona".

Docker (plataforma de contenedores) es la solución a eso: empaqueta el proyecto con todo lo que necesita —PHP, MySQL, phpMyAdmin y sus versiones exactas— en contenedores (cajas aisladas). Así corre igual en cualquier computadora con un solo comando, sin instalar nada a mano y sin pisar otros programas. Ese es su papel acá: que montar el sistema sea reproducible y no dependa de lo que cada uno tenga instalado.

Por qué tres cajas y no una sola

Por la misma razón por la que la cocina y el baño no son la misma habitación: cada pieza hace una cosa, y así se pueden tocar por separado. Si querés rearmar la aplicación, la base no se entera. Si la aplicación se rompe, los datos siguen intactos. Y si algún día cambiás la versión de MySQL, cambiás una línea y lo demás sigue igual.

Es también el modelo que vas a encontrar en cualquier servidor real, así que es buena costumbre aprenderlo acá.

La red privada

Los tres contenedores viven en una red que Docker creó solo para este proyecto, llamada tarea_crud_red. Dentro de esa red, el nombre de un contenedor funciona como una dirección. Por eso, cuando mires el archivo config.php, vas a ver que la aplicación se conecta a un servidor llamado tarea_crud_mysql.

El error clásico

Si en algún momento escribís localhost como servidor de la base, no va a funcionar. Desde dentro del contenedor de PHP, localhost es ese mismo contenedor, donde no hay ninguna base escuchando. Es como marcar tu propio número esperando que atienda el vecino.

Dónde quedan los datos

La base no guarda nada dentro de su propio contenedor. Escribe en un volumen, que es un espacio de disco aparte que Docker administra, llamado tarea_crud_mysql_datos. Los contenedores son descartables; el volumen no.

Eso tiene una consecuencia muy práctica, y conviene tenerla clara antes de borrar nada:

docker compose downApaga y borra los contenedores. Los datos sobreviven.
docker compose down -vLo mismo, y además borra el volumen. Los datos se van.

Esa -v es toda la diferencia entre "apagué el proyecto" y "empecé de cero". Usala a propósito, nunca de paso.

Un detalle de vocabulario que se confunde seguido

La pantalla que ves en el navegador — el HTML, los colores, las letras — es el frontend, y no vive en ningún contenedor: se ejecuta en tu propia máquina. Lo que corre en el servidor es el backend, y acá es PHP: lee la base, arma la página, y recién entonces te la manda terminada.

Dicho de otro modo: el contenedor tarea_crud_php no te muestra la página, la escribe. Mostrarla es trabajo de tu navegador.

ControlVerificar que funcionó

Cinco señales. Si las cinco están, el entorno quedó bien montado.

  • docker ps muestra tres contenedores corriendo: tarea_crud_mysql, tarea_crud_php y tarea_crud_phpmyadmin.
  • Al lado de tarea_crud_mysql dice (healthy). Eso significa que la base ya contesta, no solo que arrancó.
  • localhost:8001 abre la pantalla de login, con fondo gris y barra azul marino. Si se ve sin estilos, los archivos de assets/ no están llegando.
  • Después de registrarte y entrar, ves la tabla con 5 productos y tres números arriba (productos, unidades y stock bajo).
  • localhost:8081 abre phpMyAdmin. Entrás con usuario root y la contraseña que pusiste en el .env, y ahí está la base tarea_crud_db con las tablas productos y usuarios.

Base de datosConectarse a la base de datos

Hay dos formas de mirar y consultar la base de datos (BD): desde el navegador con phpMyAdmin (ya incluido, no hay que instalar nada) o con un gestor de bases de datos externo como DBeaver.

Desde el navegador: phpMyAdmin

Es la forma más rápida. Con el proyecto levantado, andá a http://localhost:8081 e iniciá sesión con:

Usuarioroot
Contraseñala que pusiste en .env (la línea DB_PASS)

El servidor ya viene configurado por dentro (apunta al contenedor tarea_crud_mysql), así que no hace falta indicar host ni puerto. Adentro vas a ver la base tarea_crud_db con sus tablas (productos, categorias, usuarios).

Desde un gestor externo (DBeaver, MySQL Workbench, etc.)

Para conectarte con un programa de escritorio, la base se publica en el puerto 3307 de tu computadora (se eligió 3307 en vez del 3306 estándar para no chocar con otro MySQL que ya tengas instalado). Creá una conexión nueva de tipo MySQL con estos datos:

Host / Servidorlocalhost (o 127.0.0.1)
Puerto3307
Base de datostarea_crud_db
Usuarioroot
Contraseñala de tu .env (DB_PASS)
Si venías de una versión anterior

El puerto 3307 lo publica docker-compose.yml con la línea "3307:3306" (host:contenedor). Si ya tenías el proyecto levantado de antes, corré una vez docker compose up -d para que el cambio tome efecto (recrea el contenedor de la base). Dentro de Docker la base sigue escuchando en el 3306; el 3307 es solo la puerta hacia afuera.

¿"Connection refused" o no conecta?

Verificá que Docker esté corriendo y la base levantada (docker compose ps), que uses el puerto 3307 (no el 3306), y que la contraseña sea exactamente la de tu .env.

Si algo fallaProblemas comunes

Casi todo lo que sale mal la primera vez está en esta lista.

Dice que falta DB_PASS

No creaste el .env, o lo dejaste sin valor. Volvé al paso 2: cp .env.example .env y escribí tu clave después del signo igual, sin espacios ni comillas.

"Cannot connect to the Docker daemon"

Docker Desktop no está abierto. Abrilo, esperá a que diga "Engine running", y repetí el comando. Es el olvido más común.

"port is already allocated" (el puerto está ocupado)

Otro programa de tu máquina ya está usando el 8001 o el 8081. Abrí el docker-compose.yml, buscá la línea - "8001:80" y cambiá el primer número, por ejemplo a - "8002:80". Después entrás por ese puerto nuevo. El segundo número no se toca.

"The container name is already in use"

Quedó un contenedor viejo del proyecto dando vueltas. Corré docker compose down --remove-orphans y volvé a levantarlo.

La página dice "Error de conexión a la base de datos"

Lo más probable es que MySQL todavía esté arrancando: esperá medio minuto y recargá. Si sigue igual, mirá qué está diciendo la aplicación con docker compose logs php.

Entré pero la lista de productos sale vacía

La base se creó, pero el archivo que arma las tablas no se ejecutó. Ese archivo corre una sola vez, cuando el volumen se crea por primera vez, así que hay que arrancar de cero: docker compose down -v y después docker compose up -d --build. Ojo que eso borra lo que hubieras cargado, usuario incluido.

La página se ve sin estilos, todo blanco y negro

Los archivos de public/assets/ no están llegando. Verificá que clonaste el repositorio completo y que la carpeta public/assets existe con css y fonts adentro.

ReferenciaComandos útiles

Todos se corren desde la carpeta del proyecto, con Docker Desktop abierto.

docker compose up -dEncender el proyecto.
docker compose downApagarlo. Los datos se conservan.
docker compose down -vApagarlo y borrar la base. Solo cuando querés empezar de cero.
docker compose up -d --buildVolver a armar la imagen de la aplicación. Hace falta si cambiaste el Dockerfile.
docker psVer qué está corriendo ahora.
docker compose logs phpVer qué dice la aplicación. Es lo primero que hay que mirar si una página sale en blanco.
docker compose logs mysqlVer qué dice la base de datos.
docker compose restart phpReiniciar solo la aplicación, sin tocar la base.
Para editar código no hace falta reconstruir nada

La carpeta del proyecto está montada dentro del contenedor, así que si cambiás un archivo .php y recargás el navegador, el cambio ya está ahí. Solo necesitás --build cuando tocás el Dockerfile.
